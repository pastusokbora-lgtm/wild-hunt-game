# Зовнішні 3D-моделі (GLB / glTF)

Гра працює й без цих файлів: для кожного об'єкта є власна процедурна модель.
Це **тимчасові** моделі — вони передають форму, пропорції й анімацію, але **не є
фотореалістичними**. Готові моделі підключаються через `assets/manifest.json`
без зміни коду гри.

## Як підключити модель

1. Покладіть файл `.glb` у потрібну папку (див. таблицю нижче). На GitHub з
   телефона: репозиторій → **Add file → Upload files** → у полі імені файлу можна
   одразу написати шлях, наприклад `assets/models/animals/deer.glb`.
2. У `assets/manifest.json` для цього ключа змініть `"enabled": false` на
   `"enabled": true` (і за потреби — `url`).
3. Оновіть сторінку гри.

Якщо файл не знайдено або він пошкоджений, гра **не зупиниться**: лишиться
процедурна модель, а на початку полювання з'явиться підказка (подробиці — у
консолі браузера).

> Моделі завантажує GLTFLoader із бібліотеки Three.js (через карту імпорту в
> `index.html`, з cdn.jsdelivr.net). Якщо браузер дуже старий або jsDelivr
> недоступний, гра працює з процедурними моделями.

### Зброя в руках

Руки тримають зброю за точками хвату процедурної моделі (руків'я, цівка, рукоятка затвора,
магазин, ключ рушниці), тому GLB має бути **в тому самому масштабі й системі координат**:
одиниці — метри, **x** — праворуч, **y** — угору, ствол (клинок) — уздовж **−Z**.

| Ключ | Початок координат | Розміри процедурної моделі |
|---|---|---|
| `rifle` | на осі каналу ствола, точно над спусковим гачком | затильник ≈ 0,35 м позаду, руків'я ≈ 0,10 м позаду й 5 см нижче осі |
| `shotgun` | на осі **верхнього** ствола, у площині казенного зрізу | стволи 0,711 м, нижній ствол на 22,5 мм нижче; шарнір — 66 мм попереду й 40,5 мм нижче; спусковий гачок ≈ 14 мм позаду |
| `knife` | у больстері (гарді) | клинок 0,118 м уздовж −Z, лезо донизу (−Y); руків'я 0,116 м уздовж +Z |

**Рухомі частини** розпізнаються за назвами вузлів у файлі (без урахування регістру) і рухаються
разом з анімацією:

| Модель | Назва вузла | Що робить |
|---|---|---|
| `rifle` | `bolt…` (або `затвор…`) | затвор: піднімається й відходить назад; положення — закритий затвор |
| `rifle` | `mag…`, `magazine…` (або `магазин…`) | відʼємний магазин (.308 Win): його виймає ліва рука |
| `shotgun` | `barrels…` (або `стволи…`) | блок стволів разом із цівкою: переламується на шарнірі |
| `shotgun` | `lever…`, `top_lever…` (або `ключ…`) | ключ відмикання над колодкою |

Якщо вузла немає, ця частина GLB лишається нерухомою (у консолі браузера буде підказка).
Набої в пальцях і в патронниках, гільзи, що вилітають, і самі руки залишаються процедурними.
Спалах пострілу з'являється біля процедурного дульного зрізу; для гвинтівки його можна задати
полем `muzzle`, висоту оптики — `scopeY`, відстань окуляра за початком координат — `eyeZ`.

Руки — готова модель кисті з набору WebXR Input Profiles («generic-hand», ліцензія MIT,
© Amazon), перетворена для гри (рукавичка без пальців, передпліччя й рукав куртки), і вбудована
в `game.js`. Замінити її через маніфест не можна: скелет рук і точки хвату розраховано саме під
цю модель (25 суглобів кисті за стандартом WebXR Hand Input).

**Вовк, лисиця й заєць-русак** — лише власні моделі гри (розділ 11c у `game.js`, генератор — у
`tools/beast-gen`): для них немає слотів GLB, бо їхня поведінка (зграя, мишкування, «стовпчик»,
виття, лежка) потребує поз, яких немає в звичайних наборах кліпів `idle/walk/run/feed/death`.
Кабан теж має власну модель із цими позами, але слот `boar` лишився: якщо підключити GLB, кабан
поводитиметься так само, а анімації братимуться з кліпів файлу.

### Анімації тварин

Гра сама перемикає кліпи за поведінкою звіра: стоїть → `idle`, пасеться (риє,
шукає їжу) → `feed`, іде → `walk`, біжить → `run`, загибель → `death` (грає один
раз і завмирає). Назви кліпів у файлі вказуються в полі `animations`; якщо його
немає, гра шукає кліпи за словами в назвах (`idle`, `walk`, `run`/`gallop`/`trot`,
`eat`/`graze`, `death`/`die`). Якщо кліпу загибелі немає, тварина просто лягає на бік.

Зони влучання (голова, шия, серце й легені, корпус, ноги) беруться з процедурного
скелета виду, тому модель має бути приблизно тих самих пропорцій і розміру, що й
справжня тварина (`fitHeight` нижче).

## Поля в `manifest.json`

| Поле | Значення |
|---|---|
| `enabled` | `true` — використовувати файл, `false` — процедурна модель |
| `url` | шлях до файлу відносно `index.html` |
| `scale` | множник розміру (за замовчуванням 1) |
| `fitHeight` | підігнати висоту моделі під задану, м (зручніше за `scale`). Для тварин — справжня висота дорослого самця від копит до верхньої точки (з рогами, якщо вони є в моделі): олень ≈ 2,4, без рогів ≈ 1,9; козуля ≈ 1,3; кабан ≈ 1,05; ведмідь ≈ 1,5. Гра трохи змінює розмір кожної особини, самки менші |
| `rotationY` | поворот навколо вертикалі, градуси (якщо модель дивиться не вздовж +Z) |
| `position` | зсув `[x, y, z]`, м |
| `offsetY` | додатковий зсув угору, м |
| `groundAlign` | `false` — не ставити найнижчу точку моделі на землю (за замовчуванням ставиться) |
| `draco` | `true` — файл стиснуто Draco (декодер підвантажиться з jsDelivr) |
| `animations` | назви кліпів: `idle`, `walk`, `run`, `feed`, `death` |
| `muzzle` | лише для `rifle`, необов'язково: точка дульного зрізу `[x, y, z]` (там з'являється спалах пострілу); без поля — як у процедурної моделі |
| `scopeY` | лише для `rifle`, необов'язково: висота осі оптичного прицілу над віссю ствола, м (щоб приціл став точно навпроти ока) |
| `eyeZ` | лише для `rifle`, необов'язково: на скільки метрів позаду початку координат окуляр прицілу |

## Рекомендації для телефонів

- Формат **GLB** (один файл, текстури всередині). Текстури 1024–2048 px у JPG,
  PNG або WebP. Стиснення Draco підтримується; KTX2/Basis і Meshopt — ні
  (для них потрібні окремі декодери).
- Трикутники: тварина — 10–30 тис., зброя в руках — 10–40 тис. (вона близько до камери), будівля — 5–20 тис.,
  дерево — до ~8 тис. (дерева повторюються сотні разів через InstancedMesh, а далекі
  замінюються «імпостерами» — знімками дерева).
- 1–3 матеріали на модель. Металевість і шорсткість (PBR) зберігаються.
- Розмір одного файлу на GitHub через браузер — до 25 МБ; для швидкого
  завантаження на телефоні краще до 5–10 МБ.
